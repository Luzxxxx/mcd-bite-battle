# 模型对手接入

## 本机配置

本机 `.env` 保留麦当劳 Token，另外填写自己的模型密钥：

```dotenv
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-flash
```

空值不是密钥。只在本机填入真实值并重启 Node 服务，不要把本机环境密钥提交、发到聊天或嵌入页面源码。默认模型名依据本轮查询的 [DeepSeek Chat Completions 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)；如果账户可用模型不同，修改 `DEEPSEEK_MODEL`。客户端直连 `https://api.deepseek.com/chat/completions`，没有第三方代理地址。

点击对手卡「用自己的 AI」，填写玩家自己的 API。支持的域名和隐私边界见 [v0.3 说明](V03_RELEASE.md)。本机 .env 的 DeepSeek 入口仍可使用；环境密钥不会发送给前端。Worker 支持访客自带 API 的训练对战，本机额外支持真实核价；部署配置见 [架构与部署](ARCHITECTURE.md)。

## 模型能做什么

服务器向模型提供规范化目标餐袋、预算、本局公开菜单、参考价和允许的券，不提供玩家方案、个人 Token、账户券或用户隐私。字段名称和菜单条目作为数据处理。

两个工具：

| 工具 | 作用 | 约束 |
| --- | --- | --- |
| `quote_plan` | 校验完全同餐与预算，取得整单实付 | 每局最多三次，失败也消耗次数；训练走规则引擎，真实走官方 MCP |
| `submit_plan` | 提交之前成功报价过的完整方案 | 原样 plan + couponId 必须已通过验证；模型口述金额不算结果 |

最多五轮模型请求、七个工具调用、每轮输出上限 1,800 token，模型请求使用 75 秒总超时信号。DeepSeek 关闭 thinking 以控制互动等待，其他服务使用其兼容工具协议。按官方工具调用格式传回工具结果，不把模型内部推理写入日志、前端或交付证据。模型报价工具仍可能耗时，界面显示备战状态。

模型未知工具、未知商品、错误数量、非法券、超预算、未报价直接提交、超过预算、HTTP 错误或超时都不能开始有效对局。失败时明确提示，保留用户选择，不悄悄用策略算法代替模型。

## 封存与揭晓

合法对手方案在玩家开始选餐前封存。默认本机对手保存在本机内存，自带模型的训练方案使用短期加密票据，不包含 API Key。服务器生成随机 nonce，并计算：

```text
SHA256(UTF8(JSON.stringify({ plan, couponId, nonce })))
```

开局只返回摘要与模型身份。揭晓返回原方案、nonce 和摘要；前端重新计算并核对。真实局还会重新向官方报价，两边都成功才能比较。承诺证明本次返回的方案与开局摘要相符，不证明模型执行环境可信，也不代表全局最优。

对手有可能找到玩家同样的好买法，因此允许平局和玩家输。模型复盘当前展示经过校验的试算次数与购买结构，不展示未经核实的“全球最低价”等宣传结论。

## 费用与边界

每次点击邀请都是一次新的备战，会产生账户 API 用量；上述调用数量限制用于约束用量，不是金额上限。重试不会自动无限进行。模型密钥和 MCP Token 均不进入分享链接和战绩卡；托管训练站只在当前后端调用中使用玩家主动填写的模型密钥，不配置开发者的模型密钥或 MCP Token。

每位玩家使用自己的 API 额度，站点不提供共享模型账户。模型工具调用协议以 [DeepSeek 官方说明](https://api-docs.deepseek.com/api/create-chat-completion/)为参考，规则与计价结果由本项目的受限工具实现决定。
